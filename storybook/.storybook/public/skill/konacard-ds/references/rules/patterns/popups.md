# 화면 패턴 — 팝업 · 바텀시트

> `konacard-ds-rule.md` 에서 옮겨 온 화면별 표준 패턴. 공통 규칙(화면 성격 분류 · 색 · 글자 · 간격 · 톤앤매너 · 하지 말 것)은 `konacard-ds-rule.md`, 다른 패턴은 같은 폴더의 다른 파일에 있음. 문서 안 § 참조는 이름으로 찾으면 됨.

## 표준 패턴 — 권한 동의 팝업

앱 첫 실행 시 여러 권한을 한 번에 요청하는 팝업.

- **대형 바텀시트** (화면 대부분 덮음)
- **팝업 상단** — 중앙에 KONA 워드마크 + 아래 헤드라인 "편리한 앱 이용을 위한 권한 동의" (Bold 검정, 중앙 정렬)
- **권한 리스트** — 각 항목: 좌측 **회색 원 배경 + 라인 아이콘 (56px)** + 우측 텍스트 (Bold 라벨 + 회색 설명 2줄)
- **필수/선택 텍스트 병기** — 라벨 옆 **회색 "(필수)" or "(선택)"** — 별표(`*`) 사용 금지
- **하단 유의사항** — `•` bullet 리스트 (도입어 생략, 헤드라인 문맥에 이미 포함)
- **하단 CTA "확인"**

## 표준 패턴 — "사용법 안내 팝업"

내정보 `#POPUP_SETTING_PW_GUIDE`, 카드 안내사항의 `#CARD_PIN_GUIDE` 등에서 반복되는 사용법 안내 팝업의 표준.

- **바텀시트 팝업** (상단 라운드, 딤 오버레이)
- **팝업 타이틀 중앙 Bold** — 명사구 (예: "보안 비밀번호 사용 안내", "카드 PIN / 결제 비밀번호 사용 안내")
- **회색 안내 카드** (`background/secondary`):
  1. 상단 중앙 **진한 보라 "중요!" pill 배지**
  2. 본문 안내 텍스트 (중앙 정렬)
  3. **dotted divider**
  4. `■` 사각 bullet 안내 리스트
- **팝업 안 카드 밖 하단 회색 부가 안내** (선택)
- **하단 CTA "확인"** (Primary 보라 채움)

## 표준 패턴 — 파괴적 확인 팝업 (폐기·해지·재발급 통합)

되돌릴 수 없는 액션(카드 폐기, 재발급 신청, 계정 해지, 연결 해제 등)의 확인 팝업 공통 구조. "사용법 안내 팝업"과 시각적으로 명확히 구분됨.

**구조 (bottomsheet, 상단 라운드 24)**

1. **팝업 헤딩 (필수)** — `popup/popup_Title` 컴포넌트의 **`type=guide` variant 사용** (§ "`popup/popup_Title` 컴포넌트 4 variant 규칙" 참조). `heading/1-bold` 24/32, **전체 보라(font/brand) 통일**, 중앙정렬 (2줄 허용). 예: "카드 폐기 전 / 꼭 확인해주세요!"
2. **회색 안내 카드** (`background/secondary`, radius 12):
   - **"중요!" pill 배지 (필수)** — brand 배경 + 흰 텍스트, 카드 안 상단 중앙 (`label` type=color color=brand 재사용)
   - **위험 안내 텍스트**:
     - 위험 사항 1개 → **중앙정렬 단일 문장** (`body/1-regular` 15/24)
     - 위험 사항 여러 개 → **bullet 리스트 좌측정렬** (`body/2-Regular` 14/22)
     - **가장 중요한 경고 1개만 빨강(`font/accent-red`)** — 파괴적 팝업 안 첫 번째 bullet 관행 (예: "재발급 신청 후에는 카드 신청을 취소할 수 없습니다.")
3. **(선택) 카드 밖 부가 설명** — `body/3-Regular` 12/18 + `font/tertiary` 좌측정렬 (계산 근거·상세)
4. **동의 체크박스 (필수)** — 카드 밖 배치.
   - 문구 예: "위의 중요 안내 사항을 모두 확인하고 {액션}을 진행하겠습니다."
   - 다중 안내 시 **계층 구조** — "전체 동의" (parent) + 개별 동의 (children, 우측 `>` 상세 진입 허용)
5. **병렬 CTA (필수)** — "취소" (좌 회색) / "**{액션명}**" (우 brand fill)
   - **CTA 활성 조건**: **동의 체크박스 체크 후에만 활성** (모든 파괴적 확인 팝업 통일 규칙)
   - CTA 라벨은 **실제 액션명 그대로 노출** ("카드 폐기", "신청 취소", "재발급 신청", "해지하기" 등) — "확인"·"삭제" 지양

**적용 예**: 카드 폐기, 재발급 신청, 계정 해지, 연결 해제, 회원 탈퇴 등.

**"사용법 안내 팝업"과의 시각적 차이**

| 요소 | 사용법 안내 팝업 | 파괴적 확인 팝업 |
|---|---|---|
| 헤딩 색 | 검정 | **전체 보라** |
| "중요!" pill | 있음 | 있음 |
| 회색 카드 | 있음 | 있음 |
| 동의 체크박스 | 없음 | **필수** |
| CTA | 단일 "확인" | **병렬 (취소 / 액션명)** |
| CTA 활성 조건 | 항상 활성 | **체크박스 체크 후 활성** |

**단순 안내 팝업(`#X_CARD_POPUP_NOTICE` 등)과의 차이**
- 단순 안내 팝업은 회색 카드·pill·체크박스 모두 없음, 헤딩 검정, 단일 확인 CTA만.

## 표준 패턴 — 온보딩·튜토리얼 가이드 팝업 시리즈

즐거운페이먼트 `_GUIDE_01~03` 등 서비스 첫 사용 시 사용법을 여러 팝업으로 순차 안내.

**구조 (bottomsheet, popup_Title `type=guide` variant)**
1. **팝업 헤딩** — `heading/1-bold` 24/32, **전체 brand**, 중앙정렬 (2줄 허용)
2. **회색 안내 카드** (`background/secondary`, radius 12):
   - **실제 UI 예시 배치** (브랜드 카드·리스트·버튼 등 축소 시각화)
   - **손가락 탭 애니메이션 이미지** (튜토리얼 인터랙션 유도)
3. **하단 페이지 인디케이터** — 여러 dots (활성 = brand fill / 비활성 = gray outline)
4. **단일 CTA "닫기"** (brand fill)

**적용 예**: 즐거운페이먼트 가이드 시리즈, 앞으로 유사 온보딩·튜토리얼

**"사용법 안내 팝업" · "파괴적 확인 팝업"과의 구분**

| 팝업 종류 | popup_Title variant | 회색 카드 안 내용 | CTA |
|---|---|---|---|
| **온보딩·튜토리얼** | `type=guide` | UI 예시 + 손가락 애니 이미지 + 페이지 인디케이터 | 단일 "닫기" |
| **사용법 안내** | `type=guide` | "중요!" pill + 설명 + `line/dotted` + `■` bullet 리스트 | 단일 "확인" |
| **파괴적 확인** | `type=guide` | "중요!" pill + 위험 안내 bullet + 동의 체크박스 | 병렬 (취소 / 액션명) |
| **단순 안내** | `type=title` | 회색 카드 없음, 흰 배경 위 bullet 리스트 | 단일 "확인" |

## 표준 패턴 — 중앙 얼럿 다이얼로그

**즉시 판단 필요한 짧은 확인·알림 전용** — 되돌릴 수 없는 액션 확인 / 조건 미충족 알림 / 에러 알림.

**구조 (Bottomsheet 아님 — 중앙 배치 다이얼로그)**
- 위치: 화면 **중앙** (딤 위)
- 크기: 320×약 200~340
- **Radius**: 사방 16 (`radius/components/popup` 16) — bottomsheet의 상단만 24와 다름
- 배경: `background/primary` 흰색

**구성**
1. **(선택) 상단 원형 아이콘** — 브랜드 원 + 흰 `!` (주의·경고 성격일 때만 사용, § "원형 알림 아이콘 3종" 참조)
2. **헤딩** — 중앙정렬 Bold (1~2줄). 가변부(`{카드명}` 등) 있으면 brand 강조
3. **서브 안내** — `body/2-Regular` + `font/secondary` 회색, 중앙정렬
4. **(선택) 경고 문구** — `font/error` 빨강 중앙정렬 (`accent-red` 6용도 중 ③ 긴급 알림 확장)
5. **병렬 CTA** — "취소" (좌 `button/tertiary` 회색) / "{액션명}" (우 brand fill), 크기 **medium (48)** — bottomsheet의 button/fixed-bottom (72)와 다름

**적용 예**
- SDK 포인트홈 전환 안내 팝업 (전환 확인)
- SDK 포인트홈 카드 미소지 알림
- 시스템 오류 알림

**Bottomsheet vs 얼럿 판단 기준**
- 정보량 많음·안내·리스트·복잡한 확인 → **Bottomsheet**
- 짧고 즉시 판단 필요 → **얼럿**

## 표준 패턴 — 결과 리포트 팝업 (다중 결과 나열)

여러 항목의 성공/실패/케이스별 결과를 리포트 형태로 보여주는 결과 화면 서브패턴.

**구조 (bottomsheet, popup_Title 사용 안 함)**
- **액션바 X만** (모달성)
- **상단 rounded (bottomsheet)**
- **헤딩 좌측정렬 검정** (heading/2-bold, 아이콘 없음, 부분 강조 없음)
  - 예: "등록하지 못한 간편결제가 있어요." / "간편결제에 카드를 등록해두었어요!"
- **결과 케이스별 회색 카드 세로 나열** (`background/secondary`, radius 12):
  - 각 카드 상단 pill 배지로 성격 표시:
    - **"등록 완료" pill** = solid brand fill + 흰 텍스트 (성공)
    - **"등록 실패" pill** = solid red fill (`font/accent-red`) + 흰 텍스트 (실패)
    - 이미 등록됨·일시적 문제 = pill 없이 헤더 문구만
  - pill 아래 중앙정렬 안내 문구 + 서비스 리스트
- **하단 CTA = 텍스트 링크 "확인"** (밑줄 없이 회색 중앙정렬, brand fill 버튼 아님)

**적용 예**: 간편결제 빠른 등록 결과 (여러 서비스 일괄 등록 후 케이스별 리포트)

**전체 화면 결과 통일 규칙과의 차이**
- 최종 완료·결과 통지 (프로세스 종료) = **전체 화면 통일** (아이콘 + 헤딩 전체 brand + fixed CTA)
- 중간 진행·부분 성공 리포트 (여러 항목 결과 정리) = **팝업형 변형** (아이콘 없음 + 헤딩 좌측정렬 검정 + 텍스트 링크 CTA)
