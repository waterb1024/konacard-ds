# Skill

KONACARD 통합 스킬. 기획서로 화면을 만드는 일과 디자인 시스템을 관리하는 일을 나눠 담당 에이전트에게 맡겨요.

<div className={styles.draft}>
  <strong>초안</strong> — 스킬을 고치면서 이 페이지도 같이 바꿔요. 설치 방법은 확정되면 채워요.
</div>

konacard-ds 스킬은 AI 에이전트가 KONACARD 화면과 디자인 시스템 작업을 도울 때 불러오는 안내서예요.

문서에 이미 있는 내용은 스킬에 옮겨 적지 않아요. 색·글꼴 같은 기본 값, 컴포넌트 명세, 화면 규칙은 디자인 시스템 문서와 Figma 원본이 기준이고, 복사본은 원본보다 먼저 낡기 때문이에요. 스킬은 요청을 세 가지로 나눠 알맞은 담당에게 넘겨요.

- **화면 만들기** — 기획서(Confluence · PRD · Figma · 이미지)를 읽고, 어떤 종류의 화면인지 판단해 계획을 세운 뒤, Figma 에 디자인 시스템 컴포넌트로 화면을 조립하고 규칙에 어긋난 곳을 점검해요
- **기존 화면 바꾸기** — 이미 있는 Figma 화면을 복제해, 복제본의 요소를 KONACARD 컴포넌트 · 텍스트 스타일 · 색 변수로 바꿔요 (원본은 그대로 둬요)
- **디자인 시스템 관리** — Figma 원본에서 값을 뽑아 Storybook 컴포넌트를 만들고, Figma 에서 코드가 보이도록 연결하고, 문서와 Figma 가 다른 곳을 바로잡아요

## File Structure

스킬은 디자인 시스템 저장소 전체를 함께 씁니다. `SKILL.md` 는 길잡이만 하고, 값과 규칙은 아래 원본 파일을 그때그때 엽니다.

```text
konacard-ds/
├── CLAUDE.md                        # 진입 지침 · 3파일 라우팅 (Claude Code 자동 로드)
├── konacard-ds-foundation.md        # 토큰: color / typography / spacing / radius / elevation / opacity
├── konacard-ds-components.md        # 12개 대분류 컴포넌트 명세 (00_Basic ~ 12_Banner)
├── konacard-ds-rule.md              # Figma 작업 규칙 · 화면 성격 분류 · 조립 원칙 · 안티패턴 · 패턴 목차
├── components.catalog.json          # Figma 컴포넌트 키 · variant 목록
├── rules/patterns/                  # 화면별 표준 패턴 (약관·공지 / 팝업 / 코나콘 / 카드·홈)
├── rules/figma-guide.md             # Figma 제작 실무 — 레이어 구조 · UI→컴포넌트 표 · 코드 예시
├── .claude/
│   ├── skills/konacard-ds/SKILL.md  # 이 스킬 (아래 원문)
│   └── agents/                      # 8개 subagent (트랙 A 화면 생산 / 트랙 B DS 유지관리)
└── storybook/                       # React Storybook — 매핑된 컴포넌트 라이브러리
```
